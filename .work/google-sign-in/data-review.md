The cleanup preflight's table list is unchanged (`.work/preview-e2e/schema.md`, step 2).
**Knowledge-text conflict (not schema).** Data-model rule 14 says "never from the token's claims beyond the user id" (`.claude/knowledge/data-model.md:65`), and the header of `token-verifier.ts:3` says `app_metadata` is never read. Criterion 4 can only narrow access, and `app_metadata` cannot be written by the user, so the rule's purpose (no self-promotion) still holds. The wording needs an amendment: deny-only use of `amr`/`app_metadata.providers` at authentication. BUILDER updates the header. I propose the rule-14 wording; CRITIC validates it.

1. `unlinkIdentity` likely needs Supabase "Manual linking" turned on. If it is off, criterion 3's unlink always fails, Google stays attached, and criterion 13 ("no Google provider") fails. Turning it on is a setting, which goes against "no setting relied on".
2. While Google stays linked, the pre-created account's owner can read the victim's Google identity data (`identities[].identity_data`, and probably `user_metadata`, which GoTrue fills on OAuth sign-in) with their password session.
