## Part c (web) — BUILDER 15.10.2026
**Approach**  Step 2 in `features/registration/RegisterStepTwo.tsx`: validates with the shared credentials schema, signs up through an injected Auth port, then `POST /api/register` with the new token (status only is read). Success calls the session seam (`SessionEntry.signIn`), the route guard sends the user to `/feed`. One Auth module, `services/auth/auth-client.ts`, the only file that imports an SDK.
**SDK choice**  `@supabase/auth-js`. It is the sign-up client itself; `supabase-js` bundles postgrest, storage and realtime clients that the web must not have (criterion 22 forbids `.from/.rpc/.storage/.channel`), so with auth-js those surfaces do not exist to misuse and less code ships. It has everything the spec needs (`signUp`, `persistSession:false`, `detectSessionInUrl:false`, `autoRefreshToken:false`). Added to `apps/web/package.json`.
**Env on Vercel**  Vite exposes only `VITE_`-prefixed variables, read at build time, and Vercel passes project variables to the build. Nothing like the project URL or a publishable key exists for the web today. Afik must add, for Preview and for Production (each pointing at its own Auth project): `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` (the publishable key only, never a secret key), then redeploy (build-time values). Local runs: the same two names in `apps/web/.env.local`. If either is missing, the Auth module answers "not configured" and the screen shows the generic text (no crash, no call).
**Decisions**  (1) The Auth port returns `{accessToken}` or `{failure:{status,code,name}}`; the mapping (taken, weak password, 429, network, unknown) is in `step2-form.ts` over those three fields, so an injected fake exercises the real mapping. (2) The body is built from the parsed step 1 (`toRegisterBody`), not the raw form, so values of an unticked choice never leave the browser. (3) The email lives in `RegistrationFlow` state (criterion 19); the password and the token live in step 2 only. "חזרה" from the retry state drops the token, and a new attempt then meets "already registered" (Q8). (4) 401 and 409 from the route after our own sign-up show the criterion 6 message (Q7, Q8). 500 and anything unexpected: generic text, no retry control. 503 and an unreachable server: retry text and "ניסיון חוזר". (5) The terms and privacy links open in a new tab, because step-1 data lives in this tab's memory only. (6) The link targets need pages: `/terms`, `/privacy`, `/recovery` added as Guest placeholder routes (`GuestPlaceholderPage`); recovery's real design is F1.6 (OP-029). (7) `productionSessionSource` is now an in-memory source that starts signed-out and can take a session; `SessionEntry` is an optional member of the seam, found by `isSessionEntry`. The e2e controllable source got `signIn()` too.
