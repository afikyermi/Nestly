## 3.1 מודל ההרשאות של Moderator

עקרון ההרשאות: Deny by Default ו-Least Privilege. Moderator מקבל רק Permission Keys שה-Admin הקצה לו במפורש. ההרשאות נבדקות גם בצד השרת/Backend ולא רק בממשק המשתמש.

| Permission Key | תחום | יכולת |
|---|---|---|
| SUPPORT_VIEW | פניות משתמשים | צפייה בתיבת הפניות, בפרטי הפנייה, נושא, משתמש, זמן וסטטוס. ללא שינוי פנייה. |
| SUPPORT_HANDLE | פניות משתמשים | טיפול בפנייה: תגובה, שינוי סטטוס והוספת הערה פנימית. דורש SUPPORT_VIEW. |
| REPORTS_VIEW | Moderation | צפייה בדיווחים על פוסט, תגובה, Listing או משתמש ובפרטי הדיווח. |
| CONTENT_MODERATE | תוכן קהילתי | הסרה/הסתרה ושחזור של פוסטים ותגובות בהתאם למדיניות Moderation. |
| MARKETPLACE_MODERATE | Marketplace | הסרה/הסתרה ושחזור של Marketplace Listings בעייתיים. |
| USER_VIEW | משתמשים | צפייה במידע תפעולי הנדרש לטיפול במשתמש. אינה מעניקה גישה חופשית ל-Tracker Data או לתוכן פרטי שאינו חלק מאירוע טיפול/דיווח. |
| USER_WARN | אכיפת משתמשים | שליחת אזהרה רשמית למשתמש ושמירת הפעולה בהיסטוריית האכיפה. דורש USER_VIEW. |
| USER_SUSPEND | אכיפת משתמשים | השעיה זמנית של חשבון והחזרתו לפעילות לפי סיום ההשעיה/החלטת גורם מורשה. דורש USER_VIEW. |
| USER_BAN | אכיפת משתמשים | חסימה מלאה של חשבון. החסימה הפיכה וניתן לבצע Unban/שחרור חסימה. דורש USER_VIEW. |
| PROFESSIONAL_VERIFY | אימות מקצועי | צפייה בבקשת אימות מקצועי ואישור/דחייה/עדכון סטטוס האימות לפי הכללים שיוגדרו. |
| ANALYTICS_VIEW | Analytics | צפייה במדדי שימוש/תפקוד מאושרים ובנתונים מצטברים שהוגדרו ל-Moderator. |
| AUDIT_LOG_VIEW | Audit | צפייה בלבד ביומן פעולות Admin/Moderator בהתאם לסקופ המורשה. אין הרשאה לשנות או למחוק רשומות. |
| COMMUNITY_CONFIG | ניהול קהילה | ניהול הגדרות קהילה תפעוליות שאינן קריטיות, כגון קטגוריות, סיבות דיווח ותצורות Moderation מאושרות. |
| SYSTEM_ANNOUNCEMENTS | הודעות מערכת | יצירה, עריכה, פרסום והסרה של הודעות מערכת רשמיות למשתמשים. |
| PRIVATE_GROUP_MODERATE | Moderation / Private Groups | גישה לתוכן Private Group לצורך טיפול ניהולי בלבד דרך כלי Moderation. אינה מקנה Membership או גלישה חופשית; דורשת REPORTS_VIEW ואת הרשאת הטיפול הרלוונטית. כל גישה/פעולה נרשמת ב-Audit Log. |

## 3.2 הרשאות ופעולות ייחודיות ל-Admin (Admin Only)

הפעולות הבאות אינן ניתנות להקצאה ל-Moderator ונשארות בידי ה-Admin בלבד:

| Admin Permission | יכולת |
|---|---|
| MODERATOR_MANAGE | יצירה/השבתה של משתמשי Moderator והקצאה, שינוי וביטול הרשאות שלהם. |
| SECURITY_SETTINGS_MANAGE | שינוי הגדרות אבטחה, Authentication והרשאות מערכת קריטיות. |
| BILLING_FINANCE_MANAGE | ניהול תשלומים, חיובים, החזרים, מחירים והגדרות כספיות של קידום/כלים שיווקיים. |
| SYSTEM_CRITICAL_SETTINGS | שינוי הגדרות מערכת קריטיות, אינטגרציות ותצורות תשתית/Production ברמת המוצר. |
| USER_DATA_EXPORT_DELETE | ייצוא או מחיקה מלאה של נתוני משתמש במסגרת בקשה/מדיניות פרטיות. |
| SENSITIVE_DATA_FULL_ACCESS | גישה מלאה לנתונים אישיים רגישים, Tracker Data ומידע פרטי שאינו נדרש לפעולת Moderator נקודתית. |
| LEGAL_POLICY_MANAGE | ניהול והחלפת Terms, Privacy Policy והגדרות משפטיות של המערכת. |
| ALGORITHM_AI_CONFIG | שינוי הגדרות, כללים או גרסאות של מנגנוני Algorithm/ML/LLM/AI לאחר שיוגדרו. |
| SPONSORED_PRODUCT_MANAGE | יצירה, עריכה, פרסום, השהיה והסרה של Sponsored Products/Brand Promotions בשלב הראשון. אין Brand User בשלב זה. |

## 3.3 אחריות ניהולית ויומן Audit

כל פעולה ניהולית של Admin או Moderator תירשם ב-Audit Log. לכל הפחות יישמרו Actor, Role, Permission שנעשה בו שימוש, Action, Target, Timestamp, Result וסיבה כאשר נדרשת. בשינוי הרשאות יישמר גם מצב לפני/אחרי. Moderator אינו יכול לשנות או למחוק רשומות Audit. מדיניות Retention המדויקת תוגדר בהמשך.

> החלטה מאושרת: Professional User אינו משתמש באותו חשבון כ-Parent/Regular User ואינו מקבל מסכי מעקב אחר ילד/הריון. אם אדם זקוק גם לחוויית הורה וגם לחשבון מקצועי, עליו לפתוח חשבון נפרד לכל סוג משתמש.
