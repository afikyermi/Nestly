# 1. מבוא

## 1.1 מטרת המסמך

מסמך זה מגדיר את הדרישות הפונקציונליות והלא-פונקציונליות של Nestly, את סוגי המשתמשים, מסכי המערכת, החוקים העסקיים, דרישות הנתונים, תרחישי השימוש והקשר בין Features לבין Components בקוד. המסמך משמש בסיס לפיתוח, לבדיקות QA ולשליטה בהיקף הפרויקט.

## 1.2 מטרת המערכת

Nestly היא רשת חברתית דיגיטלית הפתוחה למשתמשים בשלבי תכנון הריון, הריון והורות לילדים בכל גיל. הקונספט וחוויית הליבה של המוצר מתמקדים כיום בתכנון הריון, הריון והורות לילדים עד גיל 5, ובהמשך ניתן יהיה להוסיף שכבות תוכן, מעקב והתפתחות המותאמות לגילאים מבוגרים יותר.

- לקבל מידע וניסיון ממשתמשים הנמצאים בשלב דומה או שכבר עברו אותו.
- לשאול שאלות, לשתף חוויות ולהגיב לתוכן קהילתי.
- להתחבר למשתמשים ולקהילות רלוונטיים.
- לעקוב אחר שלבי תכנון הריון, הריון ופעילות הקשורה לילד/ה בהתאם למסלול המעקב.
- לקבל טיפים ומאמרים הרלוונטיים לשלב המשתמש.
- לקבל החלטות לגבי מוצרים ולהיחשף להמלצות אורגניות ולקידומים ממומנים שמסומנים בבירור.
- לאתר בעלי מקצוע, להתרשם מהפעילות והמוניטין שלהם ולנהל איתם שיחה חופשית.

## 1.3 קהל יעד

| סוג משתמש | הגדרה |
|---|---|
| Regular User | משתמש רגיל בשלבי תכנון הריון, הריון או הורות לילדים בכל גיל. חוויית הליבה וההתאמה לפי שלב מתמקדות כיום עד גיל 5. |
| Professional User | בעל מקצוע בתחום הריון/לידה/הורות, המחזיק Professional Profile ומשתתף בקהילה גם כנותן שירות. חשבון Professional אינו יוצר קשרי Friends; קשר חברתי אליו נעשה באמצעות Follow אל Professional Profile. |
| Guest | מבקר שאינו מחובר. רשאי להגיע למסכי Welcome, Login והרשמה בלבד; אין לו גישה ל-Feed, Marketplace, פרופילים, מעקבים או תוכן המערכת. |
| Admin | Super Admin יחיד המייצג את בעל המערכת. ל-Admin גישה מלאה לכל המידע, המסכים והפעולות המנהליות במערכת, ללא תלות בהרשאות נקודתיות. הוא מנהל משתמשים, תוכן, דיווחים, אימות מקצועי, תשלומים, נתוני שימוש ופניות משתמשים, והוא הגורם היחיד שיכול ליצור/להשבית Moderator ולהקצות, לשנות או לבטל את הרשאותיו. Admin הוא חשבון מערכת ואינו משתתף כמשתמש קהילה. |
| Moderator | משתמש ניהולי נפרד מה-Admin. ה-Moderator אינו מקבל הרשאות מנהליות כברירת מחדל ופועל לפי Permission Keys גרנולריים שה-Admin הקצה לו. ה-Admin רשאי להוסיף, לשנות או לבטל הרשאות בכל עת. פעולות Moderator נרשמות ב-Audit Log. Moderator הוא חשבון מערכת ואינו משתתף כמשתמש קהילה. |

## 1.4 הגדרות ומונחים

| מונח | הגדרה |
|---|---|
| Parent Journey | המסע המשתנה של המשתמש מתכנון הריון והלאה. המערכת פתוחה להורות בכל גיל; שכבות My Stage המפורטות מתמקדות כיום בתכנון הריון ועד גיל 5, עם אפשרות להרחבה לגילאים נוספים. |
| My Stage | הקשר המשתמש בהתאם למסלול המעקב הפעיל: תכנון/מחזור וביוץ, הריון ולידה, או ילד/ה. מודל מספר ילדים/כמה מסלולים במקביל עדיין דורש אישור. |
| Community | מרחב חברתי של פוסטים, שאלות, תגובות, ניסיון ושיתוף. |
| Professional Profile | פרופיל מקצועי ייעודי הכולל מידע מקצועי, תחום, ניסיון, פעילות, מוניטין ושירותים. |
| Organic Exposure | חשיפה המבוססת על רלוונטיות, פעילות ואיכות תרומה — ולא על תשלום. |
| Paid Promotion | חשיפה נוספת שנרכשה בתשלום ומסומנת כממומנת. |
| User-Initiated Conversation | שיחה שמשתמש רגיל יוזם עם בעל מקצוע. השיחה נפתחת מיד, ללא תשלום וללא מגבלת הודעות. |
| Message Request / Offer Help | פנייה יזומה אחת של בעל מקצוע בעקבות פוסט מסוים של משתמש רגיל. הפנייה אינה פותחת Chat מלא עד שהמשתמש מאשר אותה. |
| Message Request Decision | המשתמש הרגיל יכול לאשר, לדחות או להתעלם מהפנייה. רק אישור פותח שיחה חופשית בין הצדדים. |
| Professional Outreach Rule | אותו בעל מקצוע רשאי לשלוח לכל היותר פנייה יזומה אחת עבור אותו פוסט. אין מגבלה כללית על מספר פוסטים או משתמשים שונים שאליהם הוא רשאי לפנות. |
| Organic Recommendation | דירוג/המלצה/תוכן שנוצר באופן אורגני על ידי משתמשים. |
| Sponsored Content | תוכן/מוצר/פרופיל שקיבל חשיפה בתשלום וחייב להיות מסומן בבירור. |
| Marketplace Listing | פרסום מסחרי שנוצר על ידי משתמש רגיל לצורך מכירה או מסירה של מוצר לקהל המשתמשים. Marketplace Listing אינה פוסט קהילתי רגיל ואינה משמשת כשיתוף ידע. |
| Promoted Marketplace Listing | Marketplace Listing של משתמש רגיל שקיבלה קידום בתשלום. היא חייבת להיות מזוהה כפרסום מקודם של משתמש ולהיות מובחנת מפרסום של חברה/ספונסר. |
| Sponsored Product / Brand Promotion | מוצר או תוכן מסחרי שמקודם מטעם חברה, מותג או ספונסר. הוא חייב להיות מסומן ולהיות מובחן מ-Marketplace Listing. בשלב הראשון היצירה והניהול מתבצעים על ידי Admin/Back Office; אין Brand User עצמאי. |
| Tracker Data | הנתונים שנשמרים כתוצאה משימוש במעקבים, לרבות אירועי Tracker והקשר שלהם למשתמש/ילד/מסלול. הנתונים מיועדים לתיעוד, התאמה אישית, מתן טיפים/ידע ושיפור המערכת. הדרך המדויקת שבה אלגוריתמים ישתמשו בהם תוגדר במשימת האלגוריתמים, וכל שימוש ייכלל במטריצת Data Usage ויותאם למדיניות הפרטיות/התקנון שיוגדרו בהמשך. |
| Product | פריט שמוצג במערכת בהקשר מסחרי. כאשר משתמש רגיל מציע מוצר למכירה או למסירה, הוא מפורסם כ-Marketplace Listing ולא כפוסט קהילתי רגיל. כאשר מוצר מקודם מטעם חברה, מותג או ספונסר, הוא מוצג כ-Sponsored Product ומסומן בהתאם. |
| Friendship | קשר חברתי דו-כיווני בין שני Regular Users בלבד. הקשר מתחיל כ-Friend Request ונוצר רק לאחר אישור. Professional User, Admin ו-Moderator אינם צד לקשר Friends. |
| Professional Follow | קשר חד-כיווני שהיעד שלו הוא Professional Profile. Regular User או Professional User יכולים לעקוב אחר Professional Profile; Professional User אינו יכול לעקוב אחר Regular User. Follow אינו Friendship ואינו דורש אישור מהפרופיל המקצועי. |
| Public Group | קבוצה שניתנת לאיתור בחיפוש. משתמש מחובר יכול לקרוא את תוכן הקבוצה גם לפני הצטרפות; הצטרפות מיידית. רק חברי הקבוצה יכולים לפרסם פוסטים ולהגיב. |
| Private Group | קבוצה שניתנת לאיתור בחיפוש לפי פרטי הקבוצה, אך התוכן שלה אינו נחשף למי שאינו חבר. הצטרפות דורשת בקשת הצטרפות ואישור Group Owner או Group Admin, אלא אם נשלחה הזמנה ניהולית שאושרה על ידי המשתמש. |
| Group Owner | בעל הקבוצה. בעל הרשאה מלאה ברמת הקבוצה: שינוי Public/Private, מינוי/הסרת Group Admin ו-Group Moderator, העברת בעלות ומחיקת הקבוצה. |
| Group Admin | מנהל קבוצה שמונה על ידי Group Owner. יכול לאשר בקשות הצטרפות לקבוצה פרטית, להזמין/להסיר/לחסום חברים, לנהל חוקי קבוצה ותוכן מוצמד ולמנות/להסיר Group Moderator. אינו יכול להעביר בעלות, למחוק קבוצה או לשנות את סוג הקבוצה. |
| Group Moderator | תפקיד ניהול תוכן בתוך קבוצה, נפרד מ-System Moderator. יכול לטפל בפוסטים/תגובות, אזהרות/השתקות והסרת חבר בהתאם למדיניות הקבוצה; אינו מנהל בעלות, סוג קבוצה או מינוי Group Admin. |
| Top Bar | סרגל עליון גלובלי לאחר התחברות. ב-Regular/Professional הוא כולל Hamburger Menu, Global Search, Chat ו-Notifications; ב-Admin/Moderator הוא מותאם לחשבון מערכת ומציג פעולות ניהול/התראות ללא השתתפות חברתית. |
| Notification Preference | העדפת משתמש הקובעת אילו סוגי התראות In-App יוצגו לו. בשלב Mobile, קטגוריות שהמשתמש הפעיל יכולות להישלח גם כ-Push, רק כאשר Push מופעל באפליקציה והרשאת מערכת ההפעלה ניתנה. התראות Security/Critical Account נשארות חובה ב-In-App ואינן ניתנות לכיבוי. לקבוצה ניתן להגדיר All / Highlights / Off. |
| Regular Chat Request | בקשת שיחה בין שני Regular Users שאינם Friends ושאין ביניהם Conversation פעילה. הבקשה דורשת Accept או Decline מצד הנמען; רק Accept פותח שיחה חדשה. |
| Chat Block | חסימה ברמת ההודעות בלבד. היא מונעת המשך שליחת הודעות Chat בין הצדדים עד להסרת החסימה, אך אינה מסתירה חשבונות, אינה מסירה Friendship/Follow ואינה מהווה חסימה גלובלית במערכת. |
| Support Thread | שרשור שירות המקושר ל-SupportRequest ומוצג ב-Chat בשם “Support” כאשר התקבלה תגובת שירות. השרשור אינו Chat חברתי חופשי והאינטראקציה בו מוגבלת להקשר ולסטטוס של הפנייה. |
| Regular Profile Visibility | Regular User תמיד ניתן לאיתור ב-People Search. המשתמש יכול לקבוע אם פרופילו פתוח לצפייה של non-Friends (Open) או לא (Restricted). ב-Restricted, non-Friend רואה רק את ה-Basic Public Profile. ב-Open, non-Friend רואה את כל הפרופיל, אבל מידע על ילדים והריון מוצג **רק** כ-Journey Summary מלא (כולל גילאים), ו-Tracker Data — מדדים ונתונים שהמשתמש מתעד או מעלה על ילדים, הריון, מחזור וביוץ — אינו מוצג כלל. הכללים זהים לצופה Regular ולצופה Professional. |
| Basic Public Profile (מידע ציבורי בסיסי) | המידע שמוצג על Regular User לכל משתמש קהילה מחובר, בכל מצב Visibility. כולל **רק:** שם, תמונת פרופיל, Journey Summary ללא גילאים, רשימת Friends ו-Friends משותפים, ופעולת שליחת הודעה בכפוף ל-FR-CHAT-002. |
| Journey Summary (תקציר מסע) | האופן היחיד שבו מידע על ילדים והריון מוצג ל-non-Friend: מספר הילדים; גילאי הילדים (בפרופיל Open בלבד); ו"בהריון" אם קיים הריון — ללא פרטים נוספים, כגון שבוע הריון או תאריך לידה צפוי. שמות ילדים ותאריכי לידה אינם מוצגים; הגיל נגזר מתאריך הלידה. אם אין ילדים ואין הריון, מוצג המשפט "עוד אין כאן ילדים, אז הקפה עדיין מגיע חם ☕". המשפט מתאר את ההווה בלבד, אינו מניח כוונה או תכנון, ומנוסח בלשון ניטרלית מגדרית. הוא מוצג כברירת מחדל, והמשתמש יכול להסתיר אותו במתג בהגדרות הפרטיות; כשהוא מוסתר, לא מוצג דבר במקומו (OP-021). "תכנון הריון" אינו מוצג כסטטוס נפרד. |
| Anonymous Post | פוסט שהמחבר בחר לפרסם בלי שזהותו תוצג למשתמשי קהילה אחרים. המערכת שומרת את זהות המחבר האמיתי; ההסתרה חלה כלפי משתמשי קהילה בלבד. ראה FR-FEED-005. |
| Personalization Signal | אירוע או נתון מאושר שמשמש להתאמה אישית, כגון Stage, חיפוש, צפייה, Dwell Time, Save, Follow, Group Membership או Negative Feedback. שימוש כפוף להרשאות ולמגבלות הפרטיות. |
| Interest Profile | ייצוג נגזר של תחומי עניין של המשתמש לפי נושאים/קטגוריות. ב-v1 מחושב מחוקים ו-Scoring דטרמיניסטי, עם דעיכה לאורך זמן; אינו מודל ML. |
| Intent Signal | אות קצר-טווח שמייצג צורך נוכחי, למשל רצף חיפושים/פתיחות סביב מוצר או נושא מסוים. השפעתו דועכת עם הזמן. |
| Recommendation Candidate | פריט שעבר Eligibility והרשאות ומותר לשקול להצגה: Post, Group, Professional, Marketplace Listing, Product/Article או Sponsored Unit. |
| Ranking | מתן ציון והשוואת Candidates לפי אותות רלוונטיות מאושרים. ב-v1 המשקולות/ספים הם Configuration ולא לוגיקה קשיחה. |
| Re-ranking | שלב לאחר Ranking שמחיל כללי פרטיות, בטיחות, גיוון, Negative Feedback, מגבלות Sponsored ומניעת חזרתיות. |
| Impression | אירוע שבו פריט היה מוצג בפועל למשתמש במשטח מוגדר ובמיקום מוגדר, לצורכי Analytics/Ranking Evaluation. |
| Dwell Time | משך חשיפה/צריכה של פריט כפי שנמדד בממשק. משמש אות התנהגותי בלבד ואינו מוכיח שביעות רצון בפני עצמו. |

| Sponsored Eligibility | כלל שלפיו תשלום אינו מספיק להצגה: פריט ממומן חייב לעבור התאמת הקשר/קטגוריה, הרשאות, סטטוס ובטיחות לפני שניתן לשלבו כ-Sponsored. |
