## FR-FEED-001 — הצגת Feed

| שדה | הגדרה |
|---|---|
| סטטוס | מאושר — v1 Rule-Based; כפי שנבנה ב-I3 (19.10.2026) |
| Actor | Regular User / Professional User |
| תיאור | המערכת תציג Feed מותאם הכולל תוכן קהילתי ומודולי Recommendation מאושרים. Candidate Types יכולים לכלול Posts, Groups, Professionals, Marketplace/Product/Article units ו-Sponsored units בהתאם לסוג המשתמש וההרשאות. הפיד הוא מסך הנחיתה אחרי התחברות. הוא נטען בגלילה אינסופית, בלי כפתור "עוד" ובלי footer; קישורי תנאי השימוש והפרטיות נמצאים ב-Side Menu וב-Settings. בכל כרטיס פוסט: לייק, תגובה, שיתוף בפיד ושיתוף קישור (החלטות מ-11.10.2026). **כפי שנבנה ב-I3:** `/feed`, כותרת "הפיד" (PG-008). בראש הפיד שדה הכתיבה (FR-FEED-002). כרטיס מציג את הכותב (BR-079), הקהל ("כולם" / "חברים בלבד"), תגית השלב אם נבחרה, הטקסט והזמן כקישור לעמוד הפוסט (PG-055), ואחריהם שורת הפעולות והתגובות שבתוך הכרטיס (FR-FEED-003). כפתורי השיתוף מוצגים רק בפוסט שמותר לשתף, ולעולם אינם מוצגים כמושבתים (BR-064). לכל כרטיס תפריט "⋯" אחד, "פעולות נוספות לפוסט": בפוסט של הצופה — "עריכת הפוסט" (עריכה במקום, בתוך הכרטיס) ו"מחיקת הפוסט"; בשיתוף של הצופה — "מחיקת הפוסט" בלבד; בכל פוסט אחר, גם בפוסט האנונימי של הצופה — "הסתרת הפוסט" (FR-ALG-009) ו"דיווח על הפוסט" (FR-MOD-001). מחיקה מהפיד: אישור אחד, הכרטיס יורד והמשתמש נשאר בפיד. הפעולות מתבצעות במקום, לפי דפוסי האינטראקציה של `docs/design/direction.md` (NFR-USAB-004). מצב ריק: "עוד אין פוסטים בפיד", ושדה הכתיבה הוא הפעולה היחידה; כשל בטעינה — הודעה ו"ניסיון חוזר", והכרטיסים שנטענו נשארים (ERR-004); אחרי גלילה ארוכה — "חזרה למעלה". Back מעמוד פוסט מחזיר את הדפים שנטענו ואת מיקום הגלילה. Professional רואה את אותו פיד ומגיב ועושה לייק; הדירוג שלו מבוסס תוכן בלבד (FR-ALG-003, AC-061; החלטת אפיק מ-19.10.2026, DR-1). ב-I3 שיתוף והסתרה זמינים ל-Regular בלבד. |
| תנאים מוקדמים | Session פעיל. |
| קלט / Trigger | Role + Context מאושר + Personalization Signals + Eligible Content. |
| תהליך מערכת | Eligibility → Candidate Generation → Ranking → Re-ranking. ההבדל בין Regular ו-Professional מפורט ב-FR-ALG-002/003 ובסעיף 18. **כפי שנבנה ב-I3:** ה-Eligibility נאכפת רק ב-RLS: חשבון הצופה והכותב פעילים, הפוסט פעיל, קהל "חברים בלבד" רק לכותב ול-Friend, ופוסט שהצופה הסתיר או דיווח עליו אינו מוחזר לו. הדפים נשענים על תמונת מצב אחת (cursor), כך שאין חזרה ואין דילוג בין דפים. |
| פלט | Feed Units מדורגים ומסומנים לפי Organic/Sponsored. |
| מצב לאחר ביצוע | Impressions/Interactions נרשמים ב-AnalyticsEventFeature ומשפיעים על אותות עתידיים בהתאם למדיניות. ב-I3 אין אירועי שימוש; הרישום נבנה ב-I15 עם FR-DATA-001 (החלטת אפיק מ-18.10.2026, 4א). |

| תנאים מוקדמים | משתמש מחובר. אם היעד הוא Group, המשתמש חייב להיות Member פעיל בקבוצה. |
| קלט / Trigger | טקסט ותמונות, בהתאם למגבלות המדיה שייקבעו (NFR-MEDIA-001). סרטונים — בשלב מאוחר יותר. הטקסט לפי VAL-046, הקהל והתגית לפי VAL-049. |
| תהליך מערכת | בדיקת קלט/מדיה; אם ההקשר הוא Group מתבצעת בדיקת Membership והרשאת פרסום לפני שמירת הפוסט. קהל או תגית שאינם מותרים נדחים בבסיס הנתונים (ERR-045). Admin ו-Moderator אינם מפרסמים (ERR-022). |
| פלט | פוסט חדש מופיע בהתאם לכללי החשיפה. **כפי שנבנה ב-I3:** הפוסט מופיע מיד ראשון בפיד שנטען, בלי מעבר עמוד ובלי טעינה מחדש של הפיד, עם ההודעה "הפוסט פורסם" ומיקוד על הכרטיס החדש. בכשל הטקסט והבחירות נשארים, ומוצגת ההודעה "הפרסום לא הצליח. אפשר לנסות שוב" (ERR-004). |

## FR-FEED-005 — פרסום פוסט אנונימי

| שדה | הגדרה |
|---|---|
| סטטוס | מאושר (10.10.2026). כללי הפירוט נסגרו ב-OP-019; כפי שנבנה ב-I3 (19.10.2026) |
| Actor | Regular User בלבד. Professional User אינו רשאי לפרסם באופן אנונימי |
| תיאור | בעת יצירת פוסט או שאלה, Regular User יכול לבחור לפרסם באופן אנונימי, בכל מקום שבו הוא רשאי לפרסם: Feed, וכל Group שהוא Member פעיל בה. זהותו אינה מוצגת למשתמשי קהילה אחרים, והפוסט מוצג תחת זהות תצוגה אנונימית. **כפי שנבנה ב-I3:** תיבת הסימון "פרסום אנונימי" בשדה הכתיבה, לא מסומנת בכל פוסט חדש ולא נזכרת. כשהיא מסומנת בחירת הקהל אינה מוצגת, הפוסט תמיד "כולם" (החלטת אפיק מ-18.10.2026, 6א; ERR-045), ומוצגת ההודעה "השם שלכם לא יוצג לאף אחד בקהילה. צוות Nestly יכול לראות מי כתב, רק לבטיחות ואכיפה" (החלטת אפיק מ-19.10.2026, 13). כותרת הפוסט: "אנונימי", בלי תמונה ובלי קישור. המחבר רואה בעמוד הפוסט "פרסמתם את הפוסט הזה באופן אנונימי. רק אתם רואים את ההודעה הזו", ויכול לערוך את הטקסט והתגית ולמחוק; האנונימיות והקהל אינם ניתנים לשינוי אחרי הפרסום ("הפוסט אנונימי ומוצג לכולם. אי אפשר לשנות את זה"). בכרטיס בפיד הפוסט אינו מסומן כשל המחבר, גם בעיניו. |
| תנאים מוקדמים | Regular User מחובר. אם היעד הוא Group — Membership פעילה, כמו ב-FR-FEED-002. |
| קלט / Trigger | בחירת "פרסום אנונימי" ביצירת הפוסט, בנוסף לקלט של FR-FEED-002. |
| תהליך מערכת | הפוסט נשמר עם מזהה המחבר האמיתי וסימון אנונימיות. בכל תצוגה, תוצאת חיפוש, Notification ו-API, המערכת מחזירה למשתמש קהילה זהות אנונימית בלבד: ללא שם, תמונה או קישור לפרופיל. **כללים:** (1) תגובה או Reply של המחבר בשרשור הפוסט האנונימי שלו מוצגת תחת "המחבר" ולא בשמו. משתמשים אחרים אינם יכולים להגיב באופן אנונימי ב-v1. (2) פוסט אנונימי אינו מייצר Notification שמזהה את המחבר, למשל "פוסט חדש של Friend". (3) פוסט אנונימי אינו נכנס כ-Candidate ואינו מקבל Social Relevance דרך הגרף החברתי של המחבר — Friends, Follows וקבוצות משותפות — כדי שלא ניתן יהיה להסיק את זהותו. הוא מדורג לפי Stage, Interest, Quality ו-Freshness בלבד. (4) Professional רשאי לשלוח Offer Help לפוסט אנונימי (FR-SERV-005). הבקשה נמסרת למחבר בלי לחשוף את זהותו לבעל המקצוע, והזהות נחשפת רק אם המחבר מאשר את הבקשה ונפתחת שיחה.
