# 5. דרישות פונקציונליות · Moderation — דיווחים ואכיפה

## FR-MOD-001 — דיווח על תוכן או משתמש

| שדה | הגדרה |
|---|---|
| סטטוס | מאושר — סיבות הדיווח: החלטת אפיק מ-16.10.2026 |
| Actor | Regular User / Professional User |
| תיאור | המערכת תאפשר לדווח על פוסט, תגובה, משתמש (פרופיל) או הודעה בצ'אט שהמדווח קיבל (החלטת אפיק מ-20.10.2026). הדיווח נפתח כחלון נפרד, ושאר המסך מטושטש מעט. המשתמש בוחר סיבה אחת משמונה, ויכול להוסיף טקסט חופשי: תוכן שמסכן ילד · הטרדה או בריונות · תוכן מיני, אלים או מסית · חשיפת פרטים אישיים · מידע רפואי מסוכן או מטעה · התחזות · ספאם או פרסום לא קשור (כולל פוסט פרסומי בלי שיתוף ידע) · אחר. בחלון קישור לכללי הקהילה (BR-075). Admin יכול לערוך את הרשימה (FR-ADMIN-007). נקודות הכניסה — "דיווח על הפוסט" בתפריט "⋯" של כרטיס ושל עמוד פוסט שאינו של המדווח (גם בפוסט אנונימי); "דיווח על התגובה" בתפריט "⋯" של כל תגובה ותשובה של אחר; כפתור "דיווח על הפרופיל של <שם>" בפרופיל של משתמש אחר (PG-012). Professional מדווח כמו Regular. אין דיווח על משתמש מתוך פוסט אנונימי או מתגובת "המחבר", ואין דיווח על הפוסט המקורי שבתוך שיתוף. החלון: גיליון מלמטה מתחת ל-1024px, חלון קטן במרכז מ-1024px; המסך שמאחוריו מטושטש ואינו זז; Back, ‏Esc, לחיצה בחוץ או "ביטול" סוגרים בלי לשלוח, והמיקוד חוזר לפעולה שפתחה אותו (NFR-USAB-004). שמונה הסיבות בסדר שלמעלה, אף אחת אינה מסומנת מראש; "פרטים נוספים" לא חובה, עד 500 תווים, וחובה בבחירת "אחר" (VAL-048). **בכל דיווח במערכת** — פוסט, תגובה, פרופיל, הודעה, מודעה, ביקורת או מאמר — יש תמיד את הסיבה "אחר" ואת שדה הטקסט החופשי עד 500 תווים (החלטת אפיק מ-21.10.2026). "כללי הקהילה" נפתח בכרטיסייה חדשה, והקלט נשמר. |
| תנאים מוקדמים | המשתמש מחובר ויעד הדיווח זמין. אין דיווח על תוכן של המשתמש עצמו (גם על הפוסט האנונימי שלו) או על עצמו. |
| קלט / Trigger | בחירת Report, יעד, סיבה וטקסט חופשי אופציונלי. |
| תהליך מערכת | שמירת Report והעברתו ל-Admin ולממשק Moderation, בעדיפות לפי הסיבה (BR-074). **הודעה בצ'אט:** הצוות אינו רואה שיחות פרטיות. בדיווח על הודעה הצוות רואה רק את ההודעה שדווחה, לא את שאר השיחה; טקסט ההודעה אינו מועתק לדיווח, הוא נפתח רק בפעולה מפורשת של איש צוות בעל הרשאה, וכל פתיחה נרשמת ב-Audit Log (החלטת אפיק מ-20.10.2026; איזו הרשאה — OP-044). **הודעה או תגובה שדווחו** (החלטת אפיק מ-21.10.2026): הצוות פותח רק את הפריט שדווח — בלי שאר השיחה, בלי הפוסט ובלי שאר השרשור — גם אחרי שהדיווח נסגר, וכל פתיחה נרשמת ב-Audit Log (AC-161). Moderator יכול לטפל בדיווח רק אם ה-Admin הקצה לו הרשאת Moderation מתאימה. הדיווח נשמר עם המדווח המאומת, היעד, הסיבה והטקסט; רק המדווח קורא את הדיווח שלו, ואין דרך לערוך, לבטל או לקרוא אותו מחדש מהממשק. דיווח אחד לכל משתמש ויעד (ERR-046). יעד שאינו זמין למדווח, שאינו קיים או שהוא של המדווח — אותה תשובה "לא זמין". הצד המדווח אינו לומד על הדיווח: הפיד, הפוסט, השרשור, הפרופיל, העריכה והמחיקה מחזירים לו בדיוק אותו דבר לפני ואחרי. דיווח על פוסט מסיר אותו מהפיד ומעמוד הפוסט של המדווח בלבד; דיווח על תגובה או משתמש אינו משנה דבר לאיש, כולל המדווח (BR-074). דיווח על פוסט אנונימי שומר את הפוסט בלבד. כותב יכול לערוך פוסט שיש עליו דיווח פתוח; הדיווח שומר עותק של הטקסט המדווח (החלטת אפיק מ-18.10.2026). **ביקורת ומאמר של בעל מקצוע** (FR-SERV-011, FR-PRO-003): "דיווח על הביקורת" בכל ביקורת בעמוד בעל המקצוע (גם בעל המקצוע עצמו מדווח על ביקורת עליו; מי שכתב את הביקורת אינו מזוהה לאף אחד, גם לא לצוות), ו"דיווח על המאמר" במאמר של בעל מקצוע אחר. הטקסט מועתק לדיווח (במאמר — הכותרת והגוף). הטיפול כמו בפוסט: דיווח מוצדק מוחק את הביקורת או את המאמר בהרשאת CONTENT_MODERATE, עם סיבה וב-Audit Log (FR-MOD-003), והצוות אינו עורך את הטקסט. ביקורת או מאמר שהבעלים מחקו — הדיווחים הפתוחים עליהם נסגרים מעצמם ויוצאים מהתור, בלי שמירה ל-90 יום ובלי רשומה בהיסטוריית האכיפה (החלטת אפיק מ-21.10.2026). |
| פלט | אישור קליטת הדיווח. פוסט — החלון נסגר, הכרטיס יורד מהפיד, ובעמוד הפוסט מוצג "הדיווח נשלח. הפוסט לא יוצג לכם יותר" עם "חזרה לפיד"; תגובה או פרופיל — "הדיווח נשלח. הצוות יבדוק אותו", ושום דבר אחר לא משתנה. יעד לא זמין — "אי אפשר לדווח על זה. ייתכן שהתוכן כבר לא זמין". כשל רשת או שרת — החלון נשאר, הקלט נשמר, "הדיווח לא נשלח. אפשר לנסות שוב" (ERR-004). |
| מצב לאחר ביצוע | הדיווח מופיע בממשק Moderation בהתאם להרשאות. |
| בעל אחריות לוגי (Page / Feature) | טיפול בדיווחים |

## FR-MOD-002 — פעולות אכיפה על משתמשים

| שדה | הגדרה |
|---|---|
| סטטוס | מאושר |
| Actor | Admin / Moderator בהתאם להרשאה |
| תיאור | המערכת תאפשר פעולות אכיפה לפי Permission Keys: USER_WARN לאזהרה; USER_SUSPEND להשעיה זמנית; USER_BAN לחסימה מלאה הפיכה ול-Unban. Admin יכול לבצע את כל הפעולות. המערכת מציעה את השלב הבא במדרג (BR-074), וה-Actor תמיד מחליט בעצמו; אין אכיפה אוטומטית. |
| תנאים מוקדמים | Actor מחובר; Admin או Moderator עם Permission Key מתאים. Moderator אינו רשאי להפעיל אכיפה על Admin, על עצמו או על Moderator אחר. |
| קלט / Trigger | משתמש יעד + פעולה + סיבה; במקרה Suspension גם משך/מועד סיום. |
| תהליך מערכת | בדיקת Permission בצד ה-Backend; בדיקת Target; ביצוע Warning/Suspension/Ban/Unban; עדכון סטטוס החשבון ורישום Audit. ניהול/השבתת Moderator מתבצעים רק ע"י Admin דרך FR-ADMIN-004. כל פעולה דורשת סיבה כתובה, שנרשמת ב-Audit. המסך מציג את מצב החשבון, את היסטוריית האכיפה ואת השלב המוצע במדרג (BR-074); **היסטוריית האכיפה כוללת גם את התוכן שנמחק בדיווח מוצדק** (החלטת אפיק מ-21.10.2026): לכל פריט סוג התוכן, הכלל שהופר, התאריך, מי החליט ו-100 התווים הראשונים (במודעה ובמאמר — הכותרת), למחזיק USER_VIEW ול-Admin בלבד (AC-159); בחירה בשלב אחר מהמוצע נרשמת כדילוג, עם הסיבה. השעיה נבחרת ל-24 שעות, 3 ימים, 7 ימים או 30 יום; "סיום השעיה" מחזיר חשבון מושעה לפעילות לפני הזמן. השעיה שהגיע מועד סיומה מסתיימת כשהחשבון פונה למערכת בפעם הבאה. חסימה בגלל תוכן שמסכן ילד נעשית מתוך דיווח עם הסיבה הזו, ומסומנת כך ב-Audit. משתמש שהושעה או נחסם אינו קורא ואינו כותב דבר מרגע הפעולה, ותוכנו נעלם מאחרים. חיפוש חשבון בכלי הניהול הוא לפי שם בלבד, ואין רשימה של כל המשתמשים. |
| פלט | אישור הפעולה וסטטוס החשבון המעודכן. |
| מצב לאחר ביצוע | Warning נשמר ונרשם בהיסטוריה (הוא אינו סטטוס); Suspension מגביל את החשבון זמנית; Ban חוסם את החשבון במלואו אך ניתן לשחרור באמצעות Unban על ידי Admin או Moderator בעל USER_BAN. |
| בעל אחריות לוגי (Page / Feature) | מסך ניהול משתמשים / ניהול משתמשים ואכיפה / טיפול בדיווחים |

## FR-MOD-003 — טיפול בדיווחים ובתוכן מדווח

| שדה | הגדרה |
|---|---|
| סטטוס | מאושר — נגזר מ-Permission Matrix ומנגנון הדיווחים |
| Actor | Admin / Moderator בהתאם להרשאות |
| תיאור | המערכת תאפשר לפתוח תור דיווחים, לבחון Report ויעדו, לבצע פעולת טיפול מותרת ולעדכן את סטטוס הדיווח. |
| תנאים מוקדמים | Admin מחובר, או Moderator עם REPORTS_VIEW. פעולת תוכן דורשת CONTENT_MODERATE או MARKETPLACE_MODERATE; גישה לתוכן Private Group שאינו Member דורשת בנוסף PRIVATE_GROUP_MODERATE. פעולת אכיפה דורשת Permission מתאים. |
| קלט / Trigger | בחירת Report מתוך מסך תור הדיווחים. |
| תהליך מערכת | התור מציג שורה אחת לכל יעד פתוח (פוסט, תגובה או פרופיל) עם מספר הדיווחים והסיבה בעדיפות הגבוהה ביותר, ממוין לפי עדיפות הסיבה, ופוסט עם 3 דיווחים או יותר עולה בו בלי שיוסתר (BR-074); "תוכן שמסכן ילד" תמיד ראשון. פתיחת שורה מציגה את התוכן כפי שהוא עכשיו, את כל הדיווחים עליו ואת הטקסט שהועתק בעת הדיווח. סגירה: "דחיית הדיווח", "סגירה בלי שינוי בתוכן" (בפרופיל ובהודעה), או **"דיווח מוצדק: מחיקת התוכן"** עם סיבה כתובה (החלטת אפיק מ-21.10.2026; OP-053 נסגר): דיווח מוצדק על פוסט, תגובה, מודעה, ביקורת או מאמר מוחק את התוכן לצמיתות בעת ההחלטה, והמחיקה נרשמת ב-Audit Log ובהיסטוריית האכיפה של הכותב (FR-MOD-002, AC-159); אין עוד הסתרה הפיכה בטיפול בדיווח. הסגירה סוגרת את כל הדיווחים הפתוחים על היעד, ופעולה על תוכן דורשת CONTENT_MODERATE (מודעה — MARKETPLACE_MODERATE) ודיווח עליו. תוכן שהוסתר או הוסר בהחלטה קודמת אפשר לשחזר. **הסתרה אחרי דיווחים זהים** (BR-074): פריט שהוסתר מכולם אחרי דיווחים של 10 אנשים לפחות מאותה סיבה מסומן בתור "מוסתר מכולם עד ההחלטה", עם הסיבה ומספר האנשים — בלי לזהות מי דיווח — ומופיע מיד אחרי פריטי התוכן שמסכן ילד (OP-063); החלטה שסוגרת את הדיווחים מסירה את ההסתרה (AC-160). פוסט אנונימי מוצג בלי שם מחבר; Moderator או Admin חושף אותו רק בטיפול בדיווח פתוח על אותו פוסט (AC-077). **עבודת הצוות על התור** (החלטות אפיק מ-21.10.2026, BR-082): לכל שורה זמן ההמתנה מול זמן היעד — שעה לתוכן שמסכן ילד, 24 שעות לשאר — ושורה שעברה את היעד מסומנת; גם "הועבר למנהל" ומספר אנשי הצוות שפתחו אותה מסומנים. פתיחת שורה נרשמת (מי פתח ומתי) ומציגה גם את ההקשר — בפוסט: כל התגובות; בתגובה ובהודעה בצ'אט: רק הפריט שדווח, בלי הפוסט, בלי השרשור ובלי קישור לעמוד (FR-MOD-001, AC-161); את כרטיס המחבר (ותק החשבון, מספר צעדי האכיפה ב-12 החודשים האחרונים והצעד הבא במדרג, BR-074) למחזיק USER_VIEW; את מצב הטיפול (מי פתח, העברה למנהל עם ההערה); וקישור "פתיחת העמוד לבדיקה" לפוסט שדווח או לפרופיל. "סיבה מוכנה" מרשימה שקשורה לכללי הקהילה (BR-075) ממלאת את ההערה ואת הסיבה, ואפשר לערוך אותן. Moderator יכול "העברה למנהל" עם הערה (עד 500 תווים), ואפשר להעביר שוב עם הערה חדשה; ההעברה נרשמת ב-Audit Log. Admin רואה כל פריט בכל תור, מי פתח אותו ומה הועבר אליו, ויכול לטפל ולסגור כל פריט. טעינת הדיווח והיעד ובדיקת Permission. Admin רשאי לגשת לתוכן Private Group לצורך ניהול. Moderator שאינו Member יקבל גישה נקודתית רק אם הוקצתה PRIVATE_GROUP_MODERATE ובמסגרת טיפול בדיווח/אירוע ניהולי; אין בכך Membership או גלישה חופשית. לאחר מכן מתבצעת פעולה מותרת והגישה/הפעולה נרשמות ב-Audit Log. |
| פלט | Report וסטטוס הטיפול מתעדכנים; הפעולה שבוצעה משתקפת ביעד בהתאם להרשאה. |
| מצב לאחר ביצוע | הדיווח נשמר עם סטטוס טיפול והפעולה הניהולית ניתנת למעקב ב-Audit Log. דיווח פתוח על תוכן שהכותב מחק, שהגיע למועד השחרור (BR-080), נסגר כ"פג תוקף" בלי היעד ובלי התוכן (החלטת אפיק מ-18.10.2026, 3), ובלי רשומה בהיסטוריית האכיפה (החלטת אפיק מ-21.10.2026). דיווח שטופל נשמר 12 חודשים לחשבון פעיל (§13.4). |
| בעל אחריות לוגי (Page / Feature) | מסך תור הדיווחים / טיפול בדיווחים |
