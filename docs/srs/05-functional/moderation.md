# 5. דרישות פונקציונליות · Moderation — דיווחים ואכיפה

## FR-MOD-001 — דיווח על תוכן או משתמש

| שדה | הגדרה |
|---|---|
| סטטוס | מאושר — סיבות הדיווח: החלטת אפיק מ-16.10.2026 |
| Actor | Regular User / Professional User |
| תיאור | המערכת תאפשר לדווח על פוסט, תגובה או משתמש (פרופיל). הדיווח נפתח כחלון נפרד, ושאר המסך מטושטש מעט. המשתמש בוחר סיבה אחת משמונה, ויכול להוסיף טקסט חופשי: תוכן שמסכן ילד · הטרדה או בריונות · תוכן מיני, אלים או מסית · חשיפת פרטים אישיים · מידע רפואי מסוכן או מטעה · התחזות · ספאם או פרסום לא קשור (כולל פוסט פרסומי בלי שיתוף ידע) · אחר. בחלון קישור לכללי הקהילה (BR-075). Admin יכול לערוך את הרשימה (FR-ADMIN-007). נקודות הכניסה — "דיווח על הפוסט" בתפריט "⋯" של כרטיס ושל עמוד פוסט שאינו של המדווח (גם בפוסט אנונימי); "דיווח על התגובה" בתפריט "⋯" של כל תגובה ותשובה של אחר; כפתור "דיווח על הפרופיל של <שם>" בפרופיל של משתמש אחר (PG-012). Professional מדווח כמו Regular. אין דיווח על משתמש מתוך פוסט אנונימי או מתגובת "המחבר", ואין דיווח על הפוסט המקורי שבתוך שיתוף. החלון: גיליון מלמטה מתחת ל-1024px, חלון קטן במרכז מ-1024px; המסך שמאחוריו מטושטש ואינו זז; Back, ‏Esc, לחיצה בחוץ או "ביטול" סוגרים בלי לשלוח, והמיקוד חוזר לפעולה שפתחה אותו (NFR-USAB-004). שמונה הסיבות בסדר שלמעלה, אף אחת אינה מסומנת מראש; "פרטים נוספים" לא חובה, וחובה בבחירת "אחר" (VAL-048). "כללי הקהילה" נפתח בכרטיסייה חדשה, והקלט נשמר. |
| תנאים מוקדמים | המשתמש מחובר ויעד הדיווח זמין. אין דיווח על תוכן של המשתמש עצמו (גם על הפוסט האנונימי שלו) או על עצמו. |
| קלט / Trigger | בחירת Report, יעד, סיבה וטקסט חופשי אופציונלי. |
| תהליך מערכת | שמירת Report והעברתו ל-Admin ולממשק Moderation, בעדיפות לפי הסיבה (BR-074). Moderator יכול לטפל בדיווח רק אם ה-Admin הקצה לו הרשאת Moderation מתאימה. הדיווח נשמר עם המדווח המאומת, היעד, הסיבה והטקסט; רק המדווח קורא את הדיווח שלו, ואין דרך לערוך, לבטל או לקרוא אותו מחדש מהממשק. דיווח אחד לכל משתמש ויעד (ERR-046). יעד שאינו זמין למדווח, שאינו קיים או שהוא של המדווח — אותה תשובה "לא זמין". הצד המדווח אינו לומד על הדיווח: הפיד, הפוסט, השרשור, הפרופיל, העריכה והמחיקה מחזירים לו בדיוק אותו דבר לפני ואחרי. דיווח על פוסט מסיר אותו מהפיד ומעמוד הפוסט של המדווח בלבד; דיווח על תגובה או משתמש אינו משנה דבר לאיש, כולל המדווח (BR-074). דיווח על פוסט אנונימי שומר את הפוסט בלבד. כותב יכול לערוך פוסט שיש עליו דיווח פתוח; הדיווח שומר עותק של הטקסט המדווח (החלטת אפיק מ-18.10.2026). |
| פלט | אישור קליטת הדיווח. פוסט — החלון נסגר, הכרטיס יורד מהפיד, ובעמוד הפוסט מוצג "הדיווח נשלח. הפוסט לא יוצג לכם יותר" עם "חזרה לפיד"; תגובה או פרופיל — "הדיווח נשלח. הצוות יבדוק אותו", ושום דבר אחר לא משתנה. יעד לא זמין — "אי אפשר לדווח על זה. ייתכן שהתוכן כבר לא זמין". כשל רשת או שרת — החלון נשאר, הקלט נשמר, "הדיווח לא נשלח. אפשר לנסות שוב" (ERR-004). |
| מצב לאחר ביצוע | הדיווח מופיע בממשק Moderation בהתאם להרשאות. |
| בעל אחריות לוגי (Page / Feature) | טיפול בדיווחים |

## FR-MOD-002 — פעולות אכיפה על משתמשים

| שדה | הגדרה |
|---|---|
| סטטוס | מאושר |
| Actor | Admin / Moderator בהתאם להרשאה |
| תיאור | המערכת תאפשר פעולות אכיפה לפי Permission Keys: USER_WARN לאזהרה; USER_SUSPEND להשעיה זמנית; USER_BAN לחסימה מלאה הפיכה ול-Unban. Admin יכול לבצע את כל הפעולות. המערכת מציעה את השלב הבא במדרג (BR-074), וה-Actor תמיד מחליט בעצמו; אין אכיפה אוטומטית. |
| תנאים מוקדמים | Actor מחובר; Admin או Moderator עם Permission Key מתאים. Moderator אינו רשאי להפעיל אכיפה על Admin, על עצמו או על Moderator אחר. |
| קלט / Trigger | משתמש יעד + פעולה + סיבה; במקרה Suspension גם משך/מועד סיום. |
| תהליך מערכת | בדיקת Permission בצד ה-Backend; בדיקת Target; ביצוע Warning/Suspension/Ban/Unban; עדכון סטטוס החשבון ורישום Audit. ניהול/השבתת Moderator מתבצעים רק ע"י Admin דרך FR-ADMIN-004. |
| פלט | אישור הפעולה וסטטוס החשבון המעודכן. |
| מצב לאחר ביצוע | Warning נשמר; Suspension מגביל את החשבון זמנית; Ban חוסם את החשבון במלואו אך ניתן לשחרור באמצעות Unban על ידי Admin או Moderator בעל USER_BAN. |
| בעל אחריות לוגי (Page / Feature) | מסך ניהול משתמשים / ניהול משתמשים ואכיפה / טיפול בדיווחים |

## FR-MOD-003 — טיפול בדיווחים ובתוכן מדווח

| שדה | הגדרה |
|---|---|
| סטטוס | מאושר — נגזר מ-Permission Matrix ומנגנון הדיווחים |
| Actor | Admin / Moderator בהתאם להרשאות |
| תיאור | המערכת תאפשר לפתוח תור דיווחים, לבחון Report ויעדו, לבצע פעולת טיפול מותרת ולעדכן את סטטוס הדיווח. |
| תנאים מוקדמים | Admin מחובר, או Moderator עם REPORTS_VIEW. פעולת תוכן דורשת CONTENT_MODERATE או MARKETPLACE_MODERATE; גישה לתוכן Private Group שאינו Member דורשת בנוסף PRIVATE_GROUP_MODERATE. פעולת אכיפה דורשת Permission מתאים. |
| קלט / Trigger | בחירת Report מתוך מסך תור הדיווחים. |
| תהליך מערכת | התור ממוין לפי עדיפות הסיבה, ופוסט עם 3 דיווחים או יותר עולה בו בלי שיוסתר (BR-074). טעינת הדיווח והיעד ובדיקת Permission. Admin רשאי לגשת לתוכן Private Group לצורך ניהול. Moderator שאינו Member יקבל גישה נקודתית רק אם הוקצתה PRIVATE_GROUP_MODERATE ובמסגרת טיפול בדיווח/אירוע ניהולי; אין בכך Membership או גלישה חופשית. לאחר מכן מתבצעת פעולה מותרת והגישה/הפעולה נרשמות ב-Audit Log. |
| פלט | Report וסטטוס הטיפול מתעדכנים; הפעולה שבוצעה משתקפת ביעד בהתאם להרשאה. |
| מצב לאחר ביצוע | הדיווח נשמר עם סטטוס טיפול והפעולה הניהולית ניתנת למעקב ב-Audit Log. דיווח פתוח על תוכן שהכותב מחק, שהגיע למועד השחרור (BR-080), נסגר כ"פג תוקף" בלי היעד ובלי התוכן (החלטת אפיק מ-18.10.2026, 3). דיווח שטופל נשמר 12 חודשים לחשבון פעיל (§13.4). |
| בעל אחריות לוגי (Page / Feature) | מסך תור הדיווחים / טיפול בדיווחים |
