## FR-ADMIN-004 — ניהול הרשאות Moderator

| שדה | הגדרה |
|---|---|
| סטטוס | מאושר |
| Actor | Admin |
| תיאור | המערכת תאפשר ל-Admin בלבד ליצור/להשבית Moderator ולהקצות, לשנות ולבטל את Permission Keys המאושרים: SUPPORT_VIEW, SUPPORT_HANDLE, REPORTS_VIEW, CONTENT_MODERATE, MARKETPLACE_MODERATE, USER_VIEW, USER_WARN, USER_SUSPEND, USER_BAN, ANALYTICS_VIEW, AUDIT_LOG_VIEW, COMMUNITY_CONFIG, SYSTEM_ANNOUNCEMENTS, PRIVATE_GROUP_MODERATE, CHILD_DATA_VIEW (FR-ADMIN-015). PROFESSIONAL_VERIFY בוטלה עם האימות המקצועי (OP-005 נסגר, 18.10.2026). |
| תנאים מוקדמים | Admin מחובר וקיים משתמש Moderator. |
| קלט / Trigger | בחירת Moderator + בחירת Permission Keys להוספה/הסרה או השבתת Moderator. |
| תהליך מערכת | שמירת מיפוי ההרשאות, אכיפה בצד השרת ועדכון הגישה למודולים/פעולות. כל שינוי נשמר ב-Audit Log עם מצב לפני/אחרי. **יצירת Moderator:** ה-Admin יוצר הזמנה חד-פעמית עם תיאור קצר (למי ההזמנה, 2–80 תווים) ומקבל קישור הצטרפות שמוצג פעם אחת בלבד. ההזמנה תקפה 48 שעות (החלטת אפיק מ-21.10.2026), וה-Admin יכול לבטל הזמנה פתוחה. מי שקיבל את הקישור יוצר במסך ההצטרפות (PG-056) חשבון צוות חדש עם אימייל וסיסמה, נפרד מכל חשבון קהילה, ומצטרף כ-Moderator בלי אף הרשאה (Deny by Default). הזמנה משמשת פעם אחת בלבד, וחשבון שכבר קיים ב-Nestly אינו הופך ל-Moderator. **הקצאה:** הבחירה בהרשאה שתלויה בהרשאה אחרת מוסיפה גם אותה, וביטול הרשאה מבטל את ההרשאות שתלויות בה (BR-028). **השבתה:** חסימת החשבון (Ban) עם סיבה; החזרה לפעילות (Unban) עם סיבה. הנפקת הזמנה, ביטולה, ההצטרפות (עם ההזמנה שבה נעשה שימוש) וכל שינוי הרשאות נרשמים ב-Audit Log. |
| פלט | אישור עדכון הרשאות. |
| מצב לאחר ביצוע | ה-Moderator יכול לגשת רק ליכולות שהוקצו לו. Admin שומר גישה מלאה. פעולות Admin Only אינן ניתנות להקצאה ל-Moderator. |
| בעל אחריות לוגי (Page / Feature) | מסך הרשאות Moderator / ניהול הרשאות Moderator |

## FR-ADMIN-005 — Audit Log לפעולות ניהוליות

| שדה | הגדרה |
|---|---|
| סטטוס | מאושר; נוספו אירועי שחזור הסיסמה (15.10.2026) |
| Actor | System / Admin / Moderator עם AUDIT_LOG_VIEW לצפייה |
| תיאור | המערכת תרשום Audit Log לכל פעולה ניהולית משמעותית של Admin/Moderator. Moderator בעל AUDIT_LOG_VIEW יכול לצפות בלבד; אין אפשרות לשנות או למחוק רשומות דרך ממשק המוצר. **אירועי שחזור הסיסמה (FR-AUTH-003):** נרשמים ברשומה נפרדת, בשרת, באותה פעולה שבה הם קורים: `answers_saved` · `answers_changed` · `change_failed` · `change_limited` · `reset_failed` · `reset_limited` · `reset_verified`, ואחריו בדיוק אחת מהתוצאות `reset_completed` · `reset_admin_failed` (קביעת הסיסמה ב-Auth נכשלה) · `reset_revoke_failed` (הסיסמה נקבעה, סיום ה-Sessions נכשל) · `reset_email_mismatch` (האימייל הנוכחי של החשבון אינו האימייל שהוזן) · ומעבר מזהה האימייל: `handle_released` (החשבון איבד את המזהה לטענה חדשה יותר) · `handle_rekeyed` (המזהה עבר לאימייל שבאסימון). כל רשומה: סוג, מזהה משתמש כשידוע, hash של מזהה האימייל, hash של כתובת ה-IP וזמן — בלי תשובה, סיסמה או אימייל. למשתמשים רגילים ולמבקרים אין גישה אליה. |
| תנאים מוקדמים | פעולה ניהולית בוצעה, או Actor מורשה פתח את מסך Audit. |
| קלט / Trigger | פעולת ניהול / פתיחת Audit Log. |
| תהליך מערכת | שמירת Actor, Role, Permission, Action, Target, Timestamp, Result וסיבה כאשר קיימת; בשינוי הרשאה נשמר Before/After. הרישום נעשה באותה פעולה שבה הדבר קורה, ואין דרך לכתוב רשומה ידנית, לשנות או למחוק; פעולה שאי אפשר לתעד אינה מתבצעת. מסך יומן ה-Audit מציג את הרשומות מהחדשה לישנה, 50 בכל פעם, עם הזמן, התפקיד, הפעולה, היעד והסיבה. **סינון** (החלטת אפיק מ-21.10.2026): לפי פעולה, תפקיד ותקופה (היום, 7, 30 או 90 יום), ותצוגת "אירועים רגישים" — חשיפת מחבר אנונימי, פתיחת תוכן או עמוד של קבוצה פרטית, פתיחת הודעה שדווחה, שאילתה על נתוני ילדים, הענקה וביטול של הרשאה, הזמנה, ביטול והצטרפות של Moderator, חסימה ושחרור חסימה, חשד לפגיעה בילד בתמונה והעברת דיווח למנהל. הפעולות הנרשמות כוללות אזהרה, השעיה, סיום השעיה, חסימה ושחרור חסימה, הסתרה/הסרה/שחזור תוכן, סגירת דיווח, חשיפת מחבר אנונימי, שינוי הרשאה ושינוי סיבת דיווח. |
| פלט | רשומת Audit חדשה או רשימת רשומות בהתאם להרשאה. |
| מצב לאחר ביצוע | הפעולה ניתנת למעקב. Retention לחשבון פעיל: 12 חודשים (§13.4, החלטת אפיק מ-18.10.2026). |
| בעל אחריות לוגי (Page / Feature) | מסך יומן ה-Audit / יומן ה-Audit |
