# 5. דרישות פונקציונליות · Relationships & Groups — Friends, Follow וקבוצות

## FR-REL-001 — מודל Friends בין משתמשים רגילים

| שדה | הגדרה |
|---|---|
| סטטוס | מאושר (17.10.2026) |
| Actor | Regular User |
| תיאור | Relationship Model בין משתמשים רגילים מבוסס Friends בלבד. Friendship הוא קשר דו-כיווני ונוצר רק לאחר Friend Request ואישור. |
| תנאים מוקדמים | שני החשבונות פעילים מסוג Regular User. |
| קלט / Trigger | שליחת Friend Request / Accept / Decline / ביטול בקשה ששלחתי / Remove Friend. |
| תהליך מערכת | המערכת מונעת בקשת חברות לעצמי, לחשבון Professional, Admin או Moderator ומונעת Request כפולה. Accept יוצר Friendship; Decline אינו יוצר קשר; Remove Friend מסיר את הקשר החברתי בלבד ואינו סוגר Conversation שכבר נפתחה. **Decline שקט** — השולח אינו יודע על הדחייה: אצלו הבקשה נשארת ב"בקשות ששלחת", הקשר שהוא רואה נשאר "נשלחה", "ביטול" שלה מצליח כמו על בקשה ממתינה, ושליחה חוזרת שלו אינה מגיעה לנמען. נמען שדחה ואחר כך שולח בקשה לשולח — הבקשה המקורית חוזרת אליו כממתינה לאישורו. **ביטול** בקשה ששלחתי מסיר אותה משתי הרשימות, ואפשר לשלוח שוב. לכל זוג יש לכל היותר קשר פעיל אחד, גם בשליחות מקבילות (VAL-017). צד שאינו פעיל (מושעה או חסום) אינו מופיע ברשימות, ובקשה ממנו אינה ניתנת לאישור; השורה נשמרת, והוא חוזר כשהחשבון חוזר לפעילות. יעד שאינו Regular פעיל או אינו קיים — אותה תשובה "לא זמין" (ERR-016); Professional, Admin ו-Moderator אינם יכולים לבצע אף פעולה (ERR-022). כל שליחה נספרת כפתיחת פרופיל בהגבלת הקצב (NFR-SEC-006). ברשימות מוצגים שם ומזהה בלבד (17.10.2026). |
| פלט | סטטוס בקשת חברות/חברות מעודכן ורשימת Friends מתעדכנת. |
| מצב לאחר ביצוע | Friendship פעילה מאפשרת פתיחת Chat ישיר ללא Message Request ויכולות Friend-specific נוספות. Conversation קיימת יכולה להמשיך לאחר Remove Friend. חסימת משתמש מסיימת את ה-Friendship (FR-REL-002). |
| בעל אחריות לוגי (Page / Feature) | ניהול חברים / מסך החברים |

| תהליך מערכת | שמירת החסימה; מאותו רגע הפוסטים, התגובות, השם והפרופיל של כל צד אינם מוצגים לצד השני, כל צד אינו מופיע לשני בחיפוש אנשים וברשימות החברים, לא נשלחות התראות ביניהם, לא ניתן לשלוח או לאשר בקשת חברות ביניהם, וה-Friendship ובקשות פתוחות ביניהם מסתיימים. פוסט אנונימי אינו מוסתר (אין דרך לדעת של מי הוא). תוכן של צד חסום נשאר גלוי ל-Moderator או Admin המטפלים בדיווחים: חסימה אינה מסתירה תוכן מטיפול. ביטול החסימה מחזיר את הנראות; ה-Friendship אינו חוזר. אי אפשר לחסום Admin או Moderator, וחשבון יכול לחסום עד 20 פעמים ב-24 שעות. |
| פלט | "החשבון נחסם" במקום הפרופיל, עם קישור לרשימת המשתמשים החסומים. |
| מצב לאחר ביצוע | שני הצדדים אינם רואים זה את התוכן והפרופיל של זה, ואינם Friends. |

## FR-GRP-001 — סוגי קבוצות וחשיפת תוכן

| שדה | הגדרה |
|---|---|
| סטטוס | מאושר |
| Actor | Regular User / Professional User |
| תיאור | המערכת תתמוך ב-Public Group וב-Private Group. שני הסוגים ניתנים לאיתור בחיפוש, אך כללי חשיפת התוכן וההצטרפות שונים. |
| תנאים מוקדמים | משתמש מחובר. |
| קלט / Trigger | פתיחת כרטיס קבוצה/מסך קבוצה או תוצאת חיפוש. |
| תהליך מערכת | Public: שם/תיאור ותוכן גלויים לכל משתמש מחובר; הצטרפות מיידית; רק Members יכולים לפרסם/להגיב/לסמן לייק. Private: שם/תיאור גלויים לצורך Discovery; תוכן ופוסטים מוסתרים ממי שאינו Member; הצטרפות דורשת Request ואישור Owner/Admin. מסך הקבוצה מציג את הדיון (פוסטים חדשים קודם, הפוסט המוצמד בראש), את החברים (לחברי הקבוצה בלבד; בקבוצה ציבורית מי שאינו חבר רואה את מספר החברים בלבד, ובקבוצה פרטית לא את המספר), ואת התיאור והכללים. פוסט בקבוצה גלוי לכל מי שרשאי לראות את תוכן הקבוצה. לפיד הראשי של חברי הקבוצה נכנסים רק ה-Highlights שלה (FR-ALG-010: הפוסט המוצמד ופוסט שהגיע לסף), עם התווית "מתוך: <שם הקבוצה>" שמקשרת לקבוצה; כל שאר פוסטי הקבוצה מוצגים רק במסך הקבוצה. מי שאינו חבר בקבוצה אינו מקבל את ה-Highlights שלה בפיד, גם בקבוצה ציבורית, ופוסט מקבוצה פרטית מוצג רק לחבריה (בפיד, בחיפוש ובשיתוף). Highlight אנונימי מוצג בפיד כ"אנונימי", עם התווית. בדיון במסך הקבוצה אפשר לבחור בין "כל הפוסטים" ל"עיקרי הדברים" (ה-Highlights בלבד). Regular רשאי לפרסם בקבוצה גם אנונימית (OP-019). פוסט מקבוצה פרטית אינו ניתן לשיתוף בפיד. קבוצה שנמחקה ותוכנה אינם זמינים לאיש. |
| פלט | מסך קבוצה בהתאם להרשאת המשתמש ולסוג הקבוצה. |
| מצב לאחר ביצוע | אין חשיפת Private Group content למשתמש שאינו Member. |
| בעל אחריות לוגי (Page / Feature) | ניהול הקבוצות / מסך קבוצה |

## FR-GRP-002 — הצטרפות, בקשות והזמנות לקבוצה

| שדה | הגדרה |
|---|---|
| סטטוס | מאושר |
| Actor | Regular User / Professional User / Group Member / Group Owner / Group Admin |
| תיאור | המערכת תנהל Membership, Join Requests, הזמנות לקבוצות (כולל אישור הזמנה לקבוצה פרטית) והמלצה על Group לחבר. |
| תנאים מוקדמים | משתמש מחובר וקבוצה פעילה. |
| קלט / Trigger | Join / Request to Join / Invite / Accept Invite / Leave / Recommend to Friend. |
| תהליך מערכת | ב-Public Group Join הופך את המשתמש ל-Member מיד. ב-Private Group נוצרת Join Request (אחת ממתינה לכל משתמש וקבוצה, ERR-018); Owner/Admin יכולים Approve/Reject, והמבקש יכול לבטל בקשה ממתינה. הזמנה: כל חבר בקבוצה שאינו מושתק מזמין Friend פעיל שאינו חבר בקבוצה ואינו חסום בה. בקבוצה ציבורית, והזמנה של Owner או Admin בכל קבוצה, נשלחת למוזמן מיד. בקבוצה פרטית הזמנה של חבר אחר ממתינה לאישור Owner או Admin, לצד בקשות ההצטרפות; המוזמן אינו רואה אותה ואינו מקבל עליה התראה עד האישור; Owner ו-Admin מקבלים התראה על הזמנה שממתינה, והמזמין מקבל התראה כשהיא אושרה או נדחתה. הזמנה שהמזמין שלה עזב, או שהמוזמן כבר חבר, אינה מאושרת. המוזמן מאשר (ומצטרף מיד, גם לקבוצה פרטית) או דוחה. מי שאין לו Friends (Professional) אינו מזמין. המשתמש יכול לעזוב קבוצה בעצמו (לא ה-Owner, ERR-026). Regular User יכול לבצע Recommend to Friend רק כלפי Friendship פעילה, פעם אחת לכל קבוצה וחבר; הפעולה שולחת Notification עם יעד הקבוצה ואינה משנה Membership (המלצה היא התראה בלבד, הזמנה היא הצעה להצטרף). חבר מושתק אינו ממליץ. משתמש שנחסם בקבוצה (FR-GRP-003) אינו יכול להצטרף, לבקש או לקבל הזמנה עד שהחסימה מבוטלת. מסך הקבוצות מציג את ההזמנות שממתינות לתשובה, את הקבוצות של המשתמש ו-Discovery של כל הקבוצות הפעילות, עם חיפוש לפי שם או תיאור; קבוצות פעילות מוצגות קודם (FR-ALG-010). |
| פלט | Membership/JoinRequest/Invitation מעודכנים, או Notification מסוג Group Recommendation כאשר נבחרה המלצה לחבר. |
| מצב לאחר ביצוע | Notification רלוונטית נוצרת בהתאם להגדרות המשתמש. |
| בעל אחריות לוגי (Page / Feature) | ניהול הקבוצות / ניהול קבוצה |

## FR-GRP-003 — תפקידי ניהול קבוצה

| שדה | הגדרה |
|---|---|
| סטטוס | מאושר |
| Actor | Group Owner / Group Admin / Group Moderator |
| תיאור | תפקידי ניהול קבוצה נפרדים לחלוטין מ-System Admin/Moderator. |
| תנאים מוקדמים | משתמש הוא Member בקבוצה ובעל Group Role מתאים. |
| קלט / Trigger | פעולת ניהול קבוצה. |
| תהליך מערכת | היררכיה: Group Owner > Group Admin > Group Moderator > Member. Owner: שינוי Public/Private, מינוי/הסרת Admin/Moderator, העברת בעלות (ה-Owner הקודם נעשה Admin) ומחיקת הקבוצה. Admin: Join Requests, אישור הזמנות לקבוצה פרטית, Members, עריכת שם, תיאור ו-Rules, Pin וניהול Group Moderator; אינו יכול לפעול נגד Owner או Admin אחר. Group Moderator: תוכן ואכיפה על Members בלבד ואינו יכול לפעול נגד Owner/Admin/Group Moderator אחר. הסרת פוסט או תגובה של Role נמוך יותר (פוסט אנונימי נחשב של Member) היא פעולת תוכן. האכיפה על חבר (GroupMemberEnforcement), על ידי Group Moderator ומעלה כלפי Role נמוך יותר, היא שלוש פעולות בלבד: (1) אזהרה והשתקה יחד — החבר מקבל הודעה עם הסיבה (רשימה סגורה: פגיעה או שפה פוגענית, ספאם או פרסום, לא קשור לנושא הקבוצה, פגיעה בפרטיות, הפרת כללי הקבוצה, או "אחר" עם טקסט חופשי עד 500 תווים) ומושתק ל-24 שעות או ל-7 ימים: הוא רואה את הקבוצה ויכול לעזוב, אך אינו מפרסם, מגיב, מסמן לייק, מזמין או ממליץ; ההשתקה מסתיימת מעצמה, ובזמנה מוצגת לו בקבוצה הודעה עם הסיבה ומועד הסיום; אין אזהרה בלי השתקה; (2) הסרה וחסימה יחד, עם סיבה מאותה רשימה (המשתמש אינו יכול להצטרף, לבקש או להיות מוזמן עד ביטול החסימה; אפשר לחסום גם מי שאינו חבר); (3) ביטול חסימה, רק על ידי Role שאינו נמוך מזה שחסם. אין הסרה רגילה של חבר; מי שרוצה לצאת עוזב בעצמו. היסטוריית האכיפה של הקבוצה (הפעולה, החבר, הסיבה, המועד ומועד סיום ההשתקה) גלויה ל-Group Moderator ומעלה בקבוצה, וכל משתמש רואה ב"על הקבוצה" את ההיסטוריה שנוגעת בו — גם אחרי שההשתקה הסתיימה ואחרי שהוסר; אף אחד אינו רואה מי מבין המנהלים ביצע את הפעולה. ההשתקה הקיימת נשמרת בהיסטוריה גם אחרי שהסתיימה. Group Role אינו עורך תוכן שכתב אחר. Owner אינו יכול לעזוב/להימחק לפני העברת בעלות. |
| פלט | פעולת הקבוצה מתבצעת רק אם ה-Group Role מאפשר. |
| מצב לאחר ביצוע | שינויי Membership/Role/Content משתקפים בקבוצה; Enforcement מכבד היררכיית Roles. |
| בעל אחריות לוגי (Page / Feature) | ניהול קבוצה / מסך ניהול קבוצה |
