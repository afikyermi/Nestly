# 12. דרישות ממשקים חיצוניים

| ממשק | צורך | סטטוס |
|---|---|---|
| Authentication | זיהוי והתחברות של משתמשים (FR-AUTH). הספק: Supabase Auth. ההרשמה, ובהמשך הכניסה וחידוש ה-session, נעשות מהדפדפן מול Supabase Auth עם המפתח הציבורי (publishable) בלבד, כדי שהגבלת הקצב תיספר לפי ה-IP של המשתמש; האימייל והסיסמה אינם עוברים בשרת המערכת, והדפדפן אינו ניגש לבסיס הנתונים (החלטת אפיק מ-14.10.2026). שרת המערכת מאמת את ה-JWT בכל בקשה, וסוג החשבון וההרשאות נקראים מבסיס הנתונים בלבד. אין אימות אימייל: נרשמים ונכנסים מיד. Password Recovery נעשה בתוך המערכת, בלי אימייל, בשאלות אבטחה (FR-AUTH-003; OP-029 נסגר). **החריג המאושר לזרימה הזו בלבד** (החלטת אפיק מ-13.10.2026; 15.10.2026): מפתח הסוד של Supabase משמש רק בנתיב מבודד אחד בשרת. **הורחב (החלטת אפיק מ-16.10.2026, AR-1)** לקביעת סיסמה בלבד בארבע זרימות נוספות: ביטול הסיסמה בניקוי S-01, הסיסמה החדשה אחריו, החלפת סיסמה אחרי שתי התשובות, והסיסמה הראשונה בהרשמה עם Google; קביעת הסיסמה עצמה מסיימת את כל ה-Sessions של החשבון, ואין קריאת ניתוק נפרדת (17.10.2026). בשחזור, הפעולה היא שחזור סיסמה של משתמש אחד, רק אחרי ששתי התשובות אומתו בתוך ההגבלות ונרשם `reset_verified`, ורק כשהאימייל הנוכחי של המשתמש הוא האימייל שהוזן: קביעת הסיסמה וסיום כל ה-Sessions. שתי הקריאות שפועלות באסימון של המשתמש עצמו — קריאת הזהויות שלו (S-01, FR-AUTH-005) והיציאה הגלובלית בשחזור — נשלחות עם המפתח הציבורי (publishable) ולא עם מפתח הסוד, ובלי המפתח הציבורי בשרת הן נכשלות ואינן חוזרות למפתח הסוד (החלטת אפיק מ-17.10.2026, הרשאה מינימלית); האסימון נזרק ואינו מוחזר, נרשם או נשמר. המפתח עצמו אינו מוגבל על ידי Supabase (כוח service_role על כל הפרויקט), ולכן השימוש בו מוגבל לנתיב המבודד בלבד. בבסיס הנתונים הנתיב הלא-מחובר רץ בתפקיד מגודר נפרד, בלי עקיפת RLS. הסוד השני של הזרימה הוא ה-pepper של ה-hash; את שני הסודות מזין אפיק. | מאושר (החלטות מ-11.10.2026, עודכן 13.10.2026, 14.10.2026, 15.10.2026 ו-16–17.10.2026) |
| Payment Gateway | נדרש אם קידום פרופיל/כלים שיווקיים או קידום Marketplace Listing יירכשו בתוך המערכת. ספק לא נבחר; עד אז התשלום מדומה דרך ממשק תשלום אחד (NFR-SEC-007). | TBD Provider; מדומה (החלטת אפיק מ-15.10.2026) |
| Bot protection | בדיקה שקטה בהרשמה שהנרשם הוא אדם (NFR-SEC-008). הספק: Cloudflare Turnstile, המסלול החינמי. הוקם על ידי אפיק ב-17.10.2026: widget במצב Managed ל-nestly-blue.vercel.app. | מאושר והוקם (החלטת אפיק מ-15.10 ו-17.10.2026) |
| Error monitoring | ניטור שגיאות בשרת ובאתר. הספק: **Sentry** — שגיאות בלבד, בלי Session Replay ובלי Tracing. שני פרויקטים — שרת ואתר. ברמת הארגון פעילים Data Scrubber, Default Scrubbers ו-Prevent Storing of IP Addresses; לא נשלח מידע אישי. | מאושר והוקם (החלטת אפיק מ-17.10.2026) |
| Email / SMS / Push | Notification delivery ושחזור/אבטחת חשבון. בשלב Web התראות חברתיות, קבוצתיות, Marketplace, Promotion ו-System נמסרות In-App. בשלב Mobile ניתן גם Push לקטגוריות מאופשרות, בכפוף ל-Push enabled ולהרשאת מערכת ההפעלה. Email אינו בשימוש במוצר כרגע: אין אימות אימייל ואין שחזור באימייל (החלטה מ-13.10.2026). SMS אינו בשימוש, כי מספר טלפון אינו נאסף (החלטה מ-11.10.2026). | Notification channels מאושר: In-App + Mobile Push. אין ספק אימייל (13.10.2026). |
| Location / Maps | סינון בעלי מקצוע לפי אזור. **החלטת אפיק מ-18.10.2026:** המיקום הוא עיר או אזור שבוחרים מרשימה, בלי GPS ובלי מפה; אין בקשת הרשאת מיקום ואין ספק מפות. הרשימה עצמה — TBD. | מאושר (18.10.2026) |
| Media Storage | תמונות בפוסטים, בסטורי, במאמרים, ב-Marketplace Listings ובתמונות פרופיל; סרטונים בשלב מאוחר יותר. **Supabase Storage**, שני אחסונים פרטיים: תמונות המשתמשים, וסט האימון של מודל הבטיחות בנפרד (BR-076). השרת מקבל את התמונה המוקטנת מהדפדפן, מקודד אותה מחדש ושומר; משתמש מקבל קישור זמני רק לתמונה שמותר לו לראות (M1, החלטות אפיק מ-16.10.2026 ומ-20.10.2026). פורמטים, מגבלות ומדיניות — NFR-MEDIA-001. אפיק מקים את האחסונים בכל סביבה. | מאושר |
| Image check | בדיקה ברקע בשרת לכל תמונה (BR-076): NudeNet ‏(AGPL-3.0, מאושר; נבחן מחדש לפני השקה מסחרית), שרץ בשרת של המערכת בלי ספק חיצוני, מיד אחרי כל העלאה ופעם ביום בסריקת גיבוי (OP-031; החלטות אפיק מ-16.10.2026, מ-18.10.2026 ומ-20.10.2026). ספי החסימה הם הגדרה: 0.6 לחסימה, 0.25 ל"לא בטוח". | מאושר |
| CSAM scanning | הכלי החינמי של Cloudflare להשוואת תמונות למאגר מוכר של חומר פוגעני בילדים; חוסם התאמה ושולח התראה. דורש דומיין שהתמונות עוברות דרכו; מופעל לפני השקה ציבורית (M5). | מאושר, ממתין לדומיין |
| Medical hotlines | קישורי חיוג (`tel:`) למד"א 101 ולמוקדי האחיות של הקופות (FR-MENU-002). אין אינטגרציה ואין העברת נתונים. | מאושר |
| Realtime | עדכונים חיים לצ'אט ולהתראות. ב-MVP: polling. בהמשך: Supabase Realtime בערוצים פרטיים שמעבירים רק אות ("משהו השתנה") ולא תוכן; התוכן נטען דרך השרת, תחת אותן הרשאות (החלטה מ-11.10.2026). | מאושר — כיוון; הפעלה בהמשך |
| Affiliate / Commerce | קישורי Affiliate או אינטגרציה מסחרית למוצרים. **החלטת אפיק מ-18.10.2026 (OP-023):** קופונים ו-Affiliate אינם נכנסים ל-MVP; אין אינטגרציה. | מחוץ ל-MVP (18.10.2026) |
| Professional Verification | ~~אימות תעודות/מספרים אם יידרש.~~ אין אימות של בעלי מקצוע, ואין ממשק כזה (OP-005 נסגר, החלטת אפיק מ-18.10.2026). | **בוטל** (18.10.2026) |
| External Login | Google, דרך Supabase Auth (FR-AUTH-005): כניסה והרשמה, שוות-ערך לאימייל וסיסמה. ההרשאות המבוקשות מ-Google: `openid email`. Nestly לוקח את האימייל בלבד; השם והתמונה אינם נקראים ואינם מוצגים ונמחקים מה-user_metadata, וטבלת הזהויות הפנימית של Supabase שומרת אותם. Supabase משייך כניסת Google לחשבון קיים עם אותו אימייל אוטומטית; בכניסה הראשונה כזו השרת מנקה את הגישה הקודמת (FR-AUTH-005, S-01 נסגר). **הגדרות Supabase Auth:** Confirm email כבוי (אין אימות אימייל, 13.10.2026); Secure password change ו-Require current password when updating מופעלים בשני הפרויקטים (החלטת אפיק מ-16.10.2026, S-16), כי כל קביעת סיסמה עוברת בשרת; אפיק הפעיל אותן בשני הפרויקטים ב-17.10.2026. ההגדרה ב-Google Cloud והסודות — אפיק. Apple ואחרים — לא מאושר. | Google מאושר (13.10.2026); עודכן 17.10.2026 |
