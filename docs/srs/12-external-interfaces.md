# 12. דרישות ממשקים חיצוניים

| ממשק | צורך | סטטוס |
|---|---|---|
| Authentication | זיהוי והתחברות של משתמשים (FR-AUTH). הספק: Supabase Auth. ההרשמה, ובהמשך הכניסה וחידוש ה-session, נעשות מהדפדפן מול Supabase Auth עם המפתח הציבורי (publishable) בלבד, דרך מודול אחד, כדי שהגבלת הקצב תיספר לפי ה-IP של המשתמש; האימייל והסיסמה אינם עוברים בשרת המערכת, והדפדפן אינו ניגש לבסיס הנתונים (החלטת אפיק מ-14.10.2026). שרת המערכת מאמת את ה-JWT בכל בקשה, וסוג החשבון וההרשאות נקראים מבסיס הנתונים בלבד. אין אימות אימייל: נרשמים ונכנסים מיד. Password Recovery נעשה בתוך המערכת, בלי אימייל, בשאלות אבטחה (FR-AUTH-003; OP-029 נסגר). **החריג המאושר לזרימה הזו בלבד** (החלטת אפיק מ-13.10.2026; F1.6, 15.10.2026): מפתח הסוד של Supabase (`SUPABASE_SECRET_KEY`) נקרא רק בקובץ אחד, `apps/server/src/recovery/auth-admin.ts`, שהפעולה היחידה שלו היא שחזור סיסמה של משתמש אחד, אחרי ששתי התשובות אומתו בתוך ההגבלות ונרשם `reset_verified`: ארבע קריאות קבועות לפי הסדר — קריאת האימייל הנוכחי של המשתמש (אם אינו האימייל שהוזן, לא מתבצעת קריאה נוספת), קביעת הסיסמה, כניסה אחת בסיסמה החדשה, ויציאה גלובלית שמסיימת את כל ה-Sessions; האסימון נזרק ואינו מוחזר, נרשם או נשמר. בדיקת CI נכשלת אם שם המפתח או כתובות ה-admin מופיעים בקובץ אחר. המפתח עצמו אינו מוגבל על ידי Supabase (כוח service_role על כל הפרויקט), ולכן הגדר הוא הקוד ובדיקת ה-CI. בבסיס הנתונים הנתיב הלא-מחובר רץ בתפקיד מגודר נפרד, בלי עקיפת RLS. הסוד השני של הזרימה הוא ה-pepper של ה-hash; את שני הסודות מזין אפיק. | מאושר (החלטות מ-11.10.2026, עודכן 13.10.2026, 14.10.2026 ו-15.10.2026) |
| Payment Gateway | נדרש אם קידום פרופיל/כלים שיווקיים או קידום Marketplace Listing יירכשו בתוך המערכת. ספק לא נבחר; עד אז התשלום מדומה דרך ממשק תשלום אחד (NFR-SEC-007). | TBD Provider; מדומה (החלטת אפיק מ-15.10.2026) |
| Bot protection | בדיקה שקטה בהרשמה שהנרשם הוא אדם (NFR-SEC-008). הספק: Cloudflare Turnstile, המסלול החינמי. הגדרת החשבון והמפתחות — אפיק. | מאושר (החלטת אפיק מ-15.10.2026) |
| Email / SMS / Push | Notification delivery ושחזור/אבטחת חשבון. בשלב Web התראות חברתיות, קבוצתיות, Marketplace, Promotion ו-System נמסרות In-App. בשלב Mobile ניתן גם Push לקטגוריות מאופשרות, בכפוף ל-Push enabled ולהרשאת מערכת ההפעלה. Email אינו בשימוש במוצר כרגע: אין אימות אימייל ואין שחזור באימייל (החלטה מ-13.10.2026). SMS אינו בשימוש, כי מספר טלפון אינו נאסף (החלטה מ-11.10.2026). | Notification channels מאושר: In-App + Mobile Push. אין ספק אימייל (13.10.2026). |
| Location / Maps | סינון בעלי מקצוע לפי קרבה גיאוגרפית. אופן קבלת מיקום והרשאה TBD. | TBD |
| Media Storage | תמונות בפוסטים, בסטורי, במאמרים, ב-Marketplace Listings ובתמונות פרופיל; סרטונים בשלב מאוחר יותר. **Supabase Storage** (M1, החלטת אפיק מ-16.10.2026), העלאה ישירה בכתובת חתומה שהשרת מנפיק. פורמטים, מגבלות ומדיניות — NFR-MEDIA-001. | מאושר |
| Image check | בדיקה שנייה בשרת, ברקע, לכל תמונה (BR-076): מודל קוד פתוח שרץ אצלנו ב-`app_jobs`, בלי ספק חיצוני (OP-031). המודל המדויק — בתכנון I5. | מאושר |
| CSAM scanning | הכלי החינמי של Cloudflare להשוואת תמונות למאגר מוכר של חומר פוגעני בילדים; חוסם התאמה ושולח התראה. דורש דומיין שהתמונות עוברות דרכו; מופעל לפני השקה ציבורית (M5, I9). | מאושר, ממתין לדומיין |
| Medical hotlines | קישורי חיוג (`tel:`) למד"א 101 ולמוקדי האחיות של הקופות (FR-MENU-002). אין אינטגרציה ואין העברת נתונים. | מאושר |
| Realtime | עדכונים חיים לצ'אט ולהתראות. ב-MVP: polling. בהמשך: Supabase Realtime בערוצים פרטיים שמעבירים רק אות ("משהו השתנה") ולא תוכן; התוכן נטען דרך השרת, תחת אותן הרשאות (החלטה מ-11.10.2026). | מאושר — כיוון; הפעלה בהמשך |
| Affiliate / Commerce | קישורי Affiliate או אינטגרציה מסחרית למוצרים. | TBD |
| Professional Verification | אימות תעודות/מספרים אם יידרש. | TBD |
| External Login | Google, דרך Supabase Auth (FR-AUTH-005): כניסה והרשמה, שוות-ערך לאימייל וסיסמה. ההרשאות המבוקשות מ-Google: `openid email`. Nestly לוקח את האימייל בלבד; השם והתמונה אינם נקראים ואינם מוצגים ונמחקים מה-user_metadata, וטבלת הזהויות הפנימית של Supabase שומרת אותם (DR-5). Supabase משייך כניסת Google לחשבון קיים עם אותו אימייל אוטומטית (FR-AUTH-005; סיכון פתוח S-01). **הגדרות Supabase Auth:** Confirm email כבוי (אין אימות אימייל, 13.10.2026); Secure password change ו-Require current password when updating כבויים בשני הפרויקטים (17.10.2026), כדי שמשתמש Google חדש יוכל להגדיר סיסמה. כך מי שמחזיק Session פעיל יכול להחליף סיסמה בלי הסיסמה הנוכחית — פתוח, לטיפול לפני ההשקה (`security-privacy-open.md`, S-16). ההגדרה ב-Google Cloud והסודות — אפיק. Apple ואחרים — לא מאושר. | Google מאושר (13.10.2026); עודכן 17.10.2026 (F1.8) |
